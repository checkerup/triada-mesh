# Triada Council Protocol (Консилиум Триады с Jev-Арбитром)

Единый кросс-харнесный протокол автономного консилиума Триады (**Марк**, **Кат**, **Ника**) под арбитражем **Jev** (TypeSafe System One).

## 1. Триггеры активации (Auto-Dispatch Triggers)
Навык активируется автоматически в любом клиентском агенте при появлении ключевых фраз:
- `консилиум триады`
- `триада реши` / `триада разберись`
- `запусти консилиум` / `соберите консилиум`
- `триада консилиум: <тема>`
- `/triada-council`
- Указание `ID сессии` (например, `20260923_023804_05b757`) с поручением разобрать или завершить задачу силами консилиума.

## 2. Архитектура и распределение ролей

| Агент | Базовый харнесс | Модель | Роль в консилиуме |
|-------|-----------------|--------|-------------------|
| **Марк** | Antigravity | Gemini 2.5 Pro / Claude 3.7 | Системный архитектор, балансировка стратегии, синтез мнений, координация эстафеты |
| **Кат** | Hermes | Kimi k3 / Moonshot / DeepSeek R1 | Серверный инженер, эмпирические тесты, запуск фоновых демонов, сбор сырых данных |
| **Ника** | OpenCode | GLM-5.2 / GLM-5.3 | Хирург diff'ов, аудит кода, поиск скрытых рисков и логических уязвимостей |
| **Jev** | TypeSafe System One | `jev-latest` / `jev-preview` | **Независимый арбитр и судья** (`https://api.typesafe.ai/v1/systemone`) |

> ⚠️ **СТРОГИЙ ЗАПРЕТ НА ПОДМЕНУ ПОНЯТИЙ (Directive 13 / Directive 15):**
> - Запрещено подменять «Консилиум Триады» запуском локальных безымянных субагентов внутри одного харнесса. Субагенты допустимы только для фонового сбора данных внутри зоны ответственности агента. Итоговые решения и синтез вырабатываются ТОЛЬКО Триадой.
> - Запрещено путать роль Jev-судьи с мишенью для регистрации (`typesafe_farm`). Jev — это вероятностный арбитр качества и достоверности.

## 3. Регламент проведения консилиума

### Шаг 1: Изоляция контекста и постановка задачи (Context Ingestion)
1. Если передан ID сессии:
   - В Hermes: извлечь историю из `state.db` через SQLite в режиме `mode=ro`.
   - В OpenCode: извлечь историю из `opencode.db`.
   - В Antigravity: извлечь историю из `transcript.jsonl`.
2. Сформулировать предмет консилиума: факты, промежуточные результаты, блокеры и точные вопросы.

### Шаг 2: Межагентный опрос (Peer Consensus)
- Инициатор направляет бриф коллегам через `agent-mesh` / CLI:
  ```bash
  # Пример вызова Кат (Hermes)
  hermes --profile kat -z "[AGENT_HANDSHAKE]...[/AGENT_HANDSHAKE]" --yolo

  # Пример вызова Ники (OpenCode)
  opencode run --session <id> "[AGENT_HANDSHAKE]...[/AGENT_HANDSHAKE]"
  ```
- Коллеги возвращают аргументированные позиции с доказательствами (Exit code 0, логи, замеры, ссылки).
- Фиксируются точки консенсуса и расхождений.

### Шаг 3: Арбитраж Jev (System One Pacer)
Сформированный черновик решения и доказательная база передаются в `relay_dispatcher.py` или `jev_pacer.py`:
- **Для кода:** `tests_passed == true`, чистота `git diff`, отсутствие регрессий.
- **Для аналитики / исследований / стратегий:**
  1. `evidence_density` — проверяемость всех утверждений (HTTP 200, скриншоты, первоисточники).
  2. `peer_signatures` — подписи всех трёх агентов (Марк, Кат, Ника).
  3. `counterarguments` — наличие анализа рисков и контрдоводов.
  4. `scope_completeness` — 100% покрытие вопросов ТЗ.
- **Реакция на вердикт:**
  - `STALLED`: автоматический возврат на доработку дефекта (`stalled_location`).
  - `PASS`: официальное утверждение консилиума.

### Шаг 4: Фиксация и отчёт
- Протокол сохраняется в базе знаний: `vault/Wiki/reports/<task_id>.md`.
- Запись заносится в `triada-ledger.jsonl`.
- Финальный ответ представляется пользователю на русском языке.

## 4. Динамическая деградация топологии (Dynamic Duo Fallback: Триада ➔ Дуо + Jev)

Если один из агентов Триады временно недоступен (таймаут CLI, падение сокета, занятость в параллельной сессии):

1. **СТРОГИЙ ЗАПРЕТ на «соло-консилиум»**:
   - Оставшийся агент не имеет права объявлять себя «соло-консилиумом» и принимать архитектурные решения в одиночку.
2. **Правило динамического Дуо (Кворум 2/3)**:
   - Если Марк недоступен ➔ объединяются **Кат (Hermes) + Ника (OpenCode)**.
   - Если Ника недоступна ➔ объединяются **Кат (Hermes) + Марк (Antigravity)**.
   - Если Кат недоступна ➔ объединяются **Марк (Antigravity) + Ника (OpenCode)**.
   - В протоколе фиксируется: `Топология: Dynamic Duo (Агент1 + Агент2). Агент3: offline / timeout (кворум 2/3 соблюдён)`.
3. **Обязательный арбитраж Jev (Arbitration Gate)**:
   - В режиме Дуо решение считается легитимным ТОЛЬКО при прямом подтверждении независимого арбитра **Jev (TypeSafe System One)** с вердиктом `PASS`.
4. **Асинхронная нотификация (Inbox Catch-up)**:
   - В `agent_mesh/inbox/<agent>_inbox.md` выпадает сводка принятого решения, чтобы вышедший в онлайн агент мог верифицировать результат post-factum без задержки конвейера.
